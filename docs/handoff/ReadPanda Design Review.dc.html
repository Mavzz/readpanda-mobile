14iPad: the same app, more room

The iPad uses the same navigation, sheets and components as the phone, so nothing is new to learn. The extra space goes to the page: wider grids, two columns where a phone stacks, a two-page spread for reading, and Apple Pencil for ink. Shown on an 11-inch iPad (1194×834pt).

Layout

  • Width decides the layout, not the device. Under 700pt (Slide Over, narrow Split View) is the phone layout, unchanged.
  • Grids add columns instead of scaling covers: browsing is 3 columns → 5 portrait / 6 landscape, buckets 2 → 3 / 4.
  • Text never runs edge to edge. Text columns max out at 640pt, and two-column pages split about 60/40.
  • Tab bar as on the phone, centered, with icons and labels side by side. Section titles are eyebrows (rule 12c).

Reader

  • Scroll or Spread, switched in the top bar. Each orientation remembers its own choice: by default portrait scrolls and landscape shows a spread.
  • Spread uses the same anchor (page + selection + bounds), so switching modes keeps your place.
  • Room comments open in the same bottom sheet as the phone. It's capped at 640pt wide, so the text stays visible on both sides.

Apple Pencil

  • Pencil writes, a finger scrolls. No ink mode to turn on.
  • Strokes are anchored like comments, so they stay on the page through zoom, rotation and switching to Spread.
  • Ink is private. "Share to room" turns a stroke into a comment with an image of it.

Leaving a comment

  • Never inline bubbles — the page is dense already. Dots sit in the right gutter: accent = unread, dim = read.

4Reading tab — multiple books

Today the Reading tab is a single-book detail page, so a second book (room or solo) has nowhere to live. Redesign: Reading becomes a shelf of everything in progress, grouped by context; tapping a room book opens the existing pace/comments view, tapping a solo book opens a lighter detail with no social chrome.

The model

  • Every opened book gets its own readingProgressStore entry — tracking is per-book, independent of source.
  • Context is separate: room-attached (progress feeds pace + comment unlocking) vs standalone (progress only).
  • Home hero stays "most recently read, whatever its context" — the shelf is where the rest live.
  • Rooms tab remains the social index (per-room standing); Reading = my books, Rooms = our books.

Shelf rules (4a)

  • Two groups: In a room then Reading solo — the grouping answers "where does this progress go" at a glance.
  • Sort inside a group by last-read, newest first; the most recent book across both groups carries the accent Continue chevron.
  • Room rows earn a room chip + waiting-comments line; solo rows stay quiet — no fake social slots.
  • Finished books collapse to one footer link, not a section.

Solo detail (4b)

Same header anatomy as the room reading view, but no pace track and no comment feed — replaced by a single quiet upsell: "read it with friends" → Create Room pre-seeded with this book (handoff 2b). If the book later joins a room, existing progress carries over.

2Room screens — improved

From your screenshots: the create-room form and a freshly created, empty room. Both redesigned as one setup flow: create → invite → pick the book.

  • The invite-code card has a 1px primary border + glow — the loudest element on screen, violating the no-line rule, yet it isn't the user's next step.

  • No bridge to what happens next (pick book → invite) — the redesign sets that expectation.
